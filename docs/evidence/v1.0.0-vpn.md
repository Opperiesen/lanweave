# v1.0.0 VPN live evidence

## Protected read-only evidence: passed

The designated controller's VPN overview was exercised by the protected
[controller integration run 31940859290](https://github.com/Opperiesen/lanweave/actions/runs/31940859290)
at commit `bb6d68e988434b4b9bbbd8df1877e8671cc5d72c`.

The run used the documented local API-key surface for UniFi OS `5.1.19` and
UniFi Network `10.5.67`. The following paths passed without publishing
controller inventory:

- the direct VPN inventory, health and secret-free export probe;
- the installed CLI `vpn` table and JSON commands;
- the installed `lanweave-mcp` server over stdio with the official MCP client;
- the read-only capability and redaction checks.

The official overview returned normalized server, site-to-site tunnel, peer
and route collections. The route collection remained empty because the
official overview does not report route tables; health therefore preserves the
`not-reported-by-official-overview-api` coverage marker. The controller result
is an inventory observation (`inventory-only` or `not-configured`), not proof
of a configurable VPN lifecycle.

## Compatibility boundary

This evidence proves the local API-key read/export/plan overview path only. It
does not claim VPN key or profile generation, route-table or handshake
coverage, session-authentication support, cloud support or any VPN mutation.
Private keys, pre-shared keys, generated profiles and QR codes are rejected or
redacted and are absent from the protected reports and MCP stderr.

The absence of an active VPN lifecycle remains an explicit limitation. A
future release may add a separate protected lifecycle test only when an
isolated controller configuration can be exercised safely.
