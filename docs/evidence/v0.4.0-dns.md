# Lanweave v0.4.0 DNS evidence

- Date: 2026-08-15
- Adapter: `local-classic`
- Network application: `10.5.67`
- Endpoint: official local Network Integration API DNS policy family
- Authentication: protected test API key, value not recorded
- Read probe: passed; no pre-existing DNS policy was present
- Authorized lifecycle: passed; isolated `A` record create, update and
  user-managed prune
- Cleanup verification: passed; no DNS policy remained after the run

The run used a reserved documentation IPv4 value and a unique `lanweave-ci-*`
name. The test account, controller address, site, record name, API key, raw
responses and topology are intentionally excluded. The release test also
verified that a minimal DNS prune sub-plan did not execute network or WLAN
mutations.

Reproduction requires the protected integration variables documented in
[`compatibility.md`](../compatibility.md) and the explicit DNS mutation guard
in `tests/integration/conftest.py`; it must not be enabled against an ordinary
production target.
